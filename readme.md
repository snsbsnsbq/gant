# Gant AI— интерактивная диаграмма Ганта с AI-ассистентом

Веб-приложение для планирования проектов: интерактивная диаграмма Ганта с
засидированными тестовыми данными, импорт/экспорт Excel и чат-ассистент, который
на естественном языке массово редактирует план (переносит задачи, меняет
зависимости, добавляет задачи, перераспределяет исполнителей). Правки ассистента
сразу отражаются на диаграмме.

## Стек

| Слой     | Технологии                                                        | Порт  |
| -------- | ----------------------------------------------------------------- | ----- |
| Frontend | React 18, TypeScript, Vite, Tailwind, shadcn/ui, gantt-task-react | 5173  |
| Backend  | Python, FastAPI, FastMCP, Motor                                   | 8000  |
| LLM      | OpenRouter (модель `moonshotai/kimi-k3`)                          | —     |
| БД       | MongoDB 7 (с аутентификацией)                                     | 27017 |

## Быстрый старт

Нужен только Docker.

```bash
# 1. Указать ключ OpenRouter и пароль Mongo в .env (см. ниже)
# 2. Поднять весь стек
docker compose up -d --build
```

Открыть:

- **Приложение:** http://localhost:5173
- **API (Swagger):** http://localhost:8000/docs
- **MCP-эндпоинт:** http://localhost:8000/mcp

При первом запуске backend автоматически засидирует тестовый план.

### Переменные окружения (`.env`)

```
OPENROUTER_API_KEY=sk-or-v1-...      # ключ OpenRouter (для чат-ассистента)
OPENROUTER_MODEL=moonshotai/kimi-k3  # модель LLM
MONGO_USER=gant
MONGO_PASSWORD=<secret>
```

> Без `OPENROUTER_API_KEY` работает всё, кроме чата: диаграмма, импорт/экспорт
> Excel, drag-and-drop, модалка задач.

## Основной сценарий (что показать в демо)

1. Открыть приложение — сразу виден Гант с тестовыми данными.
2. **Импорт:** нажать «Импорт Excel», загрузить `sample_tasks.xlsx`.
3. **Правка через чат:** например «Переназначь все задачи Бориса на Дениса» или
   «Сдвинь тестирование на 3 дня позже» — диаграмма обновляется мгновенно.
4. **Детали:** клик по задаче открывает модалку с деталями.
5. **Экспорт:** «Экспорт Excel» скачивает обновлённый план.

Пример входного файла — [`example.xlsx`](./example.xlsx).

## Формат Excel

Колонки (русские заголовки, поддерживаются и английские алиасы):

| Задача | Описание | Исполнитель | Длительность | Предшественники |
| ------ | -------- | ----------- | ------------ | --------------- |

- **Длительность** — целое число дней.
- **Предшественники** — имена задач через запятую/точку с запятой.
- Даты начала/окончания не задаются в Excel — они **вычисляются** из
  длительностей и зависимостей (прямой проход, CPM-style).

## Архитектура

```
┌──────────────┐   /api (REST)     ┌───────────────────────────┐
│   Frontend   │ ────────────────► │          Backend          │
│ React + Vite │   /mcp            │      FastAPI + FastMCP     │
│  shadcn/ui   │ ◄──────────────── │                           │
│ gantt-task-  │                   │  ┌─────────────────────┐  │
│   react      │                   │  │ agent (LLM loop)    │  │
└──────────────┘                   │  │  → OpenRouter/Kimi  │  │
                                   │  │  → FastMCP tools ───┼──┼─┐
                                   │  └─────────────────────┘  │ │
                                   │  services (расписание) ◄──┼─┘
                                   └──────────────┬────────────┘
                                                  │ motor
                                                  ▼
                                             ┌─────────┐
                                             │ MongoDB │
                                             └─────────┘
```

**Ключевая идея:** REST и чат-ассистент меняют данные через **один общий слой**
`services.py`. Ассистент работает не напрямую, а через **FastMCP-инструменты**
(`list_tasks`, `create_task`, `update_task`, `delete_task`, `reschedule_plan`),
которые бэкенд вызывает in-memory MCP-клиентом. Те же инструменты доступны
внешним MCP-клиентам на `/mcp`.

### Поток чат-правки

```
Пользователь → POST /api/chat → agent → Kimi (OpenRouter, tool calling)
   → модель возвращает tool_calls
   → agent исполняет их через FastMCP (in-memory Client) → services → Mongo
   → результат возвращается модели → финальный ответ
Фронт после ответа перечитывает /api/tasks → диаграмма обновляется.
```

## Как использовались AI-ассистенты при разработке

Проект целиком собран в паре с AI-ассистентом (Cursor модель для простых задач composer 2.5 для сложных opus 4.8).

## Структура проекта

```
backend/
  app/
    main.py         # FastAPI, монтирование MCP, сид при старте
    routes.py       # REST: tasks CRUD, import, export, reschedule, chat
    services.py     # общий слой: Mongo + расписание + Excel
    scheduling.py   # прямой проход по зависимостям (CPM)
    excel.py        # парсинг/сборка xlsx (openpyxl)
    mcp_server.py   # FastMCP-инструменты
    agent.py        # цикл LLM (OpenRouter) + вызов MCP-инструментов
    seed.py         # тестовые данные
    models.py, db.py, config.py
frontend/
  src/
    App.tsx                 # layout: header/toolbar + Гант + чат
    components/
      GanttChart.tsx        # диаграмма (gantt-task-react)
      ChatPanel.tsx         # чат-ассистент
      TaskDialog.tsx        # модалка деталей задачи
      ui/                   # shadcn/ui компоненты
    api.ts, lib/
docker-compose.yml
example.xlsx          # пример входного Excel
ROADMAP.md                  # Roadmap to production
```
