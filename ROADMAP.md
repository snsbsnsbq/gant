# Roadmap to production


## Сознательно оставленные технические долги

- **Одная диаграмма без разделения на пользователей/проекты.** 
  Нет мультитенантности, авторизации, разграничения доступа.
- **Импорт полностью заменяет план** (`replace_all`). Нет слияния, версий,
  отмены действий (undo/redo). Нет RBAC. 
- **CORS `*` и открытый порт Mongo (27017)** для удобства локальной разработки.
- **Нет тестов.** 
  Нет бэкэнд тестов, нет фронтенд тестов.
- **Планирование в календарных днях.** Не учитываются выходные, праздники,
  рабочие календари и параллельная загрузка исполнителей.
- **Чат без стриминга.** Ответ приходит целиком; при длинных цепочках инструментов
  пользователь ждёт без прогресса. Прямой вопрос-ответ. Реализовать через очередь тасок. 
  Промежуточные смены статусов вызовы тулов слать на фронт через сокет события.
  Добавить рендер markdown ответов, добавить голосовой ввод.
- **История чата хранится только на клиенте** и передаётся целиком в каждый запрос.
-
- **Ошибки инструментов возвращаются агенту как текст**, без строгой типизации и
  ретраев, фалбэков.

## Чего не хватает для продакшена

### Безопасность и доступ
- Аутентификация/авторизация пользователей (OAuth/OIDC), роли.
- Rate limiting и квоты на LLM-вызовы обработки ошибок..

### Надёжность и данные
- Индексы в Mongo, бэкапы.
- Обработка конкурентных правок.
- Валидация графа зависимостей: явное обнаружение и подсветка циклов в UI.

### Продуктовые функции
- Мультипроектность.
- Undo/redo и история изменений (в т.ч. «что сделал ассистент»).
- Рабочие календари, учёт загрузки и конфликтов ресурсов.
- Совместное редактирование в реальном времени (WebSocket) вместо ре-фетча.

### Наблюдаемость и качество
- Логи (структурные), метрики, трейсинг (в т.ч. токены/стоимость LLM-запросов).
- CI/CD: линт, типы, тесты, сборка образов, автодеплой.
- Обработка ошибок и деградации при недоступности LLM (fallback-режим).


## Порядок закрытия (предлагаемый)

1. **Фундамент безопасности:** auth пользователей, API,  открытая бд, секрет-менеджер.
2. **Мультитенантность:** сущности «проект» и «пользователь», привязка задач.
3. **Надёжность данных:** индексы, версионирование.
4. **UX-безопасность правок:** preview/apply для агента, undo/redo, подсветка циклов.
5. **Тесты и CI/CD:** покрыть планировщик и парсер, e2e основного сценария,
   пайплайн деплоя.
6. **Наблюдаемость:** логи/метрики/трейсинг, учёт стоимости LLM.
7. **Продуктовые фичи:** критический путь, календари ресурсов, стриминг чата,
   реалтайм-совместная работа.
